🔌 Backend API Routes

ℹ️ Production API Endpoints: These are the RESTful API routes that would be called in a production deployment on AWS Fargate.

🔐 Authentication & Authorization

POST /api/v1/auth/login

Authenticate clinician with SSO + MFA. Returns JWT token.

POST /api/v1/auth/refresh

Refresh expired JWT token.

POST /api/v1/auth/logout

Invalidate session and revoke token.

📁 File Upload & Storage

POST /api/v1/claims/upload

Upload audio file to Amazon S3. Returns S3 path and upload_id.

GET /api/v1/claims/upload/{upload_id}

Check upload status and retrieve metadata.

DELETE /api/v1/claims/upload/{upload_id}

Delete uploaded file (with audit log).

🎤 Speech-to-Text Processing

POST /api/v1/transcription/start

Trigger Amazon Transcribe for audio transcription.

GET /api/v1/transcription/{job_id}

Poll transcription job status and retrieve result.

POST /api/v1/transcription/{job_id}/cancel

Cancel ongoing transcription job.

🔍 HITL Gate 1: Transcription Review

POST /api/v1/hitl/transcription/approve

Medical professional approves transcription accuracy.

POST /api/v1/hitl/transcription/reject

Request corrections or re-transcription.

PUT /api/v1/hitl/transcription/{job_id}/edit

Edit transcription text with version tracking.

🤖 AI Code Extraction (Amazon SageMaker)

POST /api/v1/ai/extract-codes

Amazon SageMaker analyzes transcription and suggests CPT/ICD codes.

GET /api/v1/ai/suggestions/{claim_id}

Retrieve AI-generated code suggestions with confidence scores.

POST /api/v1/ai/feedback

Submit feedback to improve AI model (reinforcement learning).

💾 Code Validation (Amazon RDS)

GET /api/v1/codes/validate

Validate CPT/ICD codes against reference database.

GET /api/v1/codes/search

Search for CPT/ICD codes by keyword or description.

GET /api/v1/codes/compatibility

Check if CPT and ICD codes are compatible for billing.

🔍 HITL Gate 2: Medical Coding Review

POST /api/v1/hitl/codes/approve

Certified coder approves CPT/ICD code selection.

PUT /api/v1/hitl/codes/modify

Coder modifies codes with justification notes.

POST /api/v1/hitl/codes/reject

Reject codes and send back to AI for re-analysis.

🏥 AWS HealthLake (FHIR & EDI)

POST /api/v1/fhir/create-claim

Create FHIR Claim resource in AWS HealthLake.

GET /api/v1/fhir/claim/{claim_id}

Retrieve FHIR Claim resource.

POST /api/v1/edi/generate-837

Generate EDI 837 Professional claim format from FHIR data.

GET /api/v1/edi/{edi_file_id}

Download generated EDI 837 file.

🔍 HITL Gate 3: Final Billing Review

POST /api/v1/hitl/billing/approve

Billing specialist approves claim for submission.

POST /api/v1/hitl/billing/hold

Place claim on hold for additional review.

POST /api/v1/hitl/billing/reject

Reject claim and send back for corrections.

📡 Event Publishing (SNS/SQS)

POST /api/v1/pubsub/publish

Publish claim events to SNS/SQS topics for async processing.

GET /api/v1/pubsub/topics

List available SNS/SQS topics.

🚀 External Submission

POST /api/v1/clearinghouse/submit

Submit EDI 837 to external clearinghouse (Availity, Change Healthcare, etc.).

GET /api/v1/clearinghouse/status/{submission_id}

Check submission status and payer response.

GET /api/v1/clearinghouse/acknowledgment/{submission_id}

Retrieve 997/999 functional acknowledgment.

📊 Analytics (Amazon Redshift)

POST /api/v1/analytics/store

Store claim data in Amazon Redshift for analytics and reporting.

GET /api/v1/analytics/reports

Generate reports: denial rates, revenue, turnaround time.

GET /api/v1/analytics/metrics

Real-time metrics dashboard data.

🔐 Audit & Compliance

GET /api/v1/audit/logs

Query CloudTrail Logs for compliance reporting.

GET /api/v1/audit/access/{resource_id}

Track who accessed specific patient/claim data.

POST /api/v1/audit/event

Log custom audit events for HIPAA compliance.

💡 API Architecture Notes:
  • Base URL: https://api.revclear.health (hosted on AWS Fargate)
  • Authentication: JWT Bearer tokens in Authorization header
  • Rate Limiting: 1000 requests/minute per user
  • Versioning: URL path versioning (v1, v2, etc.)
  • Response Format: JSON with standard error codes
  • Encryption: TLS 1.3 for all communications
  • CORS: Configured for approved frontend origins only
  • Monitoring: All endpoints logged to CloudWatch Logs

AWS Components Overview

🌐 Frontend & Security Layer

Load Balancer: HTTPS/SSL termination and traffic distribution

AWS WAF & Shield: Web Application Firewall with DDoS protection and threat detection

Amazon Cognito: SSO and MFA authentication for clinicians

⚙️ Application Layer

AWS Fargate: Serverless container platform with auto-scaling for the claims application

AWS Secrets Manager: Secure storage for API keys, database credentials, and certificates

Amazon VPC: Private network connectivity with traffic isolation

🤖 AI/ML Services

Amazon Transcribe: Converts audio recordings to text with medical vocabulary support

Amazon SageMaker: Custom ML models for diagnosis extraction and CPT/ICD code suggestion

AWS HealthLake: FHIR-compliant data storage and EDI 837 generation

💾 Data Layer

Amazon S3: Object storage for audio files and documents (encrypted at rest)

Amazon RDS PostgreSQL: Relational database for CPT reference data and patient history

Amazon Redshift: Data warehouse for claims analytics and reporting

🔐 Security & Compliance

AWS KMS: Key Management Service with 3 separate encryption keys for S3, RDS, and Redshift

AWS CloudTrail: Comprehensive logging of all access and changes (HIPAA requirement)

Amazon CloudWatch: Application monitoring and service health tracking

📡 Event & Integration Layer

Amazon SNS/SQS: Asynchronous messaging for claim events and workflow orchestration

External Clearinghouse Integration: Secure API connection for claim submission

🔒 HIPAA Compliance & Security

ℹ️ HIPAA Compliance: This architecture implements comprehensive security controls to meet HIPAA requirements for Protected Health Information (PHI).

🔐 Encryption

  • At Rest: All data encrypted using AWS KMS with customer-managed keys
  • In Transit: TLS 1.3 encryption for all network communication
  • Key Rotation: Automatic key rotation every 90 days
  • Separate Keys: Individual encryption keys for S3, RDS, and Redshift

👤 Access Control

  • Authentication: SSO with Multi-Factor Authentication (MFA) required
  • Authorization: IAM roles following principle of least privilege
  • VPC Service Controls: Network perimeter to prevent data exfiltration
  • Private Service Access: Resources not exposed to public internet

📊 Audit & Monitoring

  • AWS CloudTrail: Admin activity, data access, and system events logged
  • Log Retention: 7-year retention for HIPAA compliance
  • Real-time Monitoring: Amazon CloudWatch tracks service health and anomalies
  • Alerting: Automated alerts for security events and policy violations

🔍 Human-in-the-Loop (HITL) Gates

Three mandatory validation gates ensure accuracy and compliance:

  • Gate 1: Transcription accuracy validation by medical professional
  • Gate 2: CPT/ICD code validation by certified medical coder
  • Gate 3: Final billing compliance review before submission

HITL gates prevent automated errors and ensure regulatory compliance

🛡️ Threat Protection

  • AWS WAF & Shield: DDoS protection and WAF rules
  • AWS Security Hub: Threat detection and vulnerability scanning
  • Private Endpoints: No direct internet exposure for databases
  • Regular Audits: Automated compliance scanning and manual security reviews
